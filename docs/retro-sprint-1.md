# Retrospective of Sprint 1
We agreed that we will have to be a bit more flexible for Sprint 2.
As we did not realize how many conflicts would arise when adhering to the intended structure, as we originally decided
on a few select files, we might work a bit more dynamically with the issues.  

As next week's focus will be on implementing the client - as an interactive part to our API - we realize there might arise some overlapping between each others' segments/methods. We're most likely ready to deal with conflicts again, because the other alternative is that we all create separate files, and put everything into a single one later on, which in practice is like a lazy merge. 

In short, we weren't fully ready how the project would scale, especially with the changes of roles in the group.
We'll work within the scope that we have, and deal with the project for what it is; too small to logically break it up perfectly between 4 contributors.
